# PWA Install & Mobile Verification

## When to use this

End of the PWA phase, and before any production deploy. "It works on localhost" tells
you nothing about installability — service workers and install prompts behave
differently on a real HTTPS origin.

## Steps

1. `npm run build && npm run preview`. Fix any build warning about chunk size > 500 kB
   by lazy-loading routes before continuing.
2. **Manifest:** confirm `dist/manifest.webmanifest` has `name`, `short_name`,
   `start_url: "/"`, `display: "standalone"`, `theme_color: "#0284c7"`,
   `background_color: "#f8fafc"`, and 192/512 icons including a `maskable` variant.
   Resolve the conflict between `public/manifest.json` and the `VitePWA` manifest —
   there must be exactly one manifest; `vite-plugin-pwa` generates it, so the static
   `public/manifest.json` should be deleted.
3. **Icons:** verify every referenced icon file actually exists in `public/`
   (`pwa-192x192.png`, `pwa-512x512.png`, `apple-touch-icon.png`, `favicon.svg`,
   `masked-icon.svg`). A 404 icon silently blocks the install prompt on Android.
4. **Service worker:** confirm it registers, `registerType: 'autoUpdate'` picks up a new
   build, and an update toast prompts the user to reload rather than swapping content
   mid-session.
5. **Offline shell:** with the network throttled to offline, the app shell and the last
   feed page render with a clear "You're offline" banner. It must not show a blank
   white screen.
6. **Android Chrome:** the `beforeinstallprompt` event is captured and surfaced as the
   custom "Add to Home Screen" banner; dismissing it is remembered in `localStorage`.
7. **iOS Safari:** `beforeinstallprompt` does not exist. Detect iOS + not-standalone and
   show instructions ("Tap Share → Add to Home Screen") instead. Also verify:
   - `apple-mobile-web-app-capable` and status-bar meta tags present
   - safe-area insets respected so the bottom nav clears the home indicator
   - inputs use `font-size: 16px` so iOS doesn't zoom on focus
8. **Lighthouse** (mobile preset) on the preview build. Budgets: PWA installable ✅,
   Performance ≥ 85, Accessibility ≥ 95, Best Practices ≥ 95.
9. Report each item as PASS/FAIL with the observed value, not a summary.

## Conventions to follow

- One manifest, generated by `vite-plugin-pwa` in `vite.config.ts`.
- Never cache Supabase API responses in the service worker — stale listings and stale
  auth tokens are worse than a loading spinner. Cache the app shell and static assets only.
- The install banner never blocks content and never reappears within 30 days of dismissal.
